# APNA BUSINESS — Stages 4–9: implementation plan and true status

## Implemented in this extension
- Separate `src/drafts.js` manual approval workflow and `posting_drafts` database table.
- Four authenticated company-scoped routes for list/create/approve/reject drafts.
- Human approval is REQUIRED to post a draft; validation and balancing run again on actual posting.
- Tests for approval, duplicate protection, rejection, and cross-company account checks.

This is NOT an AI model: it does not read images, PDFs or Excel, and it does not automatically create accounting drafts from documents. Draft Approvals frontend exists in the current source snapshot.

## Stage 4 — Accounting
Full unpaid invoice credit/debit notes now exist in the latest patch; still needed: partial returns, refunds, paid-invoice adjustments, GST treatment for actual classifications, multiwarehouse/batches, automatic bank reconciliation. Review taxes with qualified professionals.

## Stage 5 — Frontend
Existing vanilla JavaScript frontend; NOT React. Draft Approval, Bank Reconciliation and whole-unpaid-invoice return screens are available. End-to-end browser tests and full usability/a11y review are still needed.

## Stage 6 — AI and Document Processing
Implement provider adapters using server-side environment secrets; antivirus/type checks, scanned-document extraction, per-company scoping, a draft preview and user approval before posting. Do not directly trust OCR/LLM outputs. No real OCR/PDF/audio adapters included here.

## Stage 7 — SaaS
Use a supported payment provider's test environment, server-side signature-verified webhooks, payment event deduplication and a subscription entitlement state machine. Never turn on a paid plan from a client callback alone. No payment gateway or paid activation included here.

## Stage 8 — Testing
Run `npm test`. Current tests do not replace security, GST, performance, payment and backup/restore reviews.

## Stage 9 — Launch
Web deployment requires persistent DB, backups, HTTPS, identity hardening, operations monitoring and policy/legal reviews. APK and EXE outputs are not generated by these source files.

## Example API workflow (authenticated OWNER/ACCOUNTANT)
1. GET /api/companies/:companyId/accounts to discover account IDs.
2. POST /api/companies/:companyId/drafts (JSON): {"date":"2026-10-14","memo":"Capital received","lines":[{"account_id":"ACTUAL_CASH_ACCOUNT_ID","debit_paise":10000,"credit_paise":0},{"account_id":"ACTUAL_CAPITAL_ACCOUNT_ID","debit_paise":0,"credit_paise":10000}]}.
3. GET /api/companies/:companyId/drafts.
4. POST /api/companies/:companyId/drafts/:draftId/approve with JSON body {} and X-CSRF-Token from login; or /reject.
